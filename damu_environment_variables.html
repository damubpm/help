Переменные окружения DAMU* и OPENSHIFT_*

Подробный справочник по переменным окружения DAMU*, DAMUCRM* и OPENSHIFT_*, которые используются в предоставленных исходниках Go. Описание основано на фактических обращениях os.Getenv() и окружающей логике кода.

34 переменныеDAMU / DAMUCRMOPENSHIFTGoSessionsRedisDatabase
Важно. Справочник описывает поведение предоставленных исходников и дополнительного фрагмента инициализации приложения. Переменные с префиксом OPENSHIFT_ здесь рассматриваются как обычные переменные окружения: код не проверяет, запущено ли приложение фактически в OpenShift. Если та же переменная используется в других частях проекта, ее итоговое влияние может быть шире.

Ключевые комбинации

Обычные DB-сессии

DAMU_REDIS_SESSION не равен 1, DAMU_DISABLE_DB_USER_SESSION не равен 1. Сессии записываются и проверяются через таблицу user_session.

Redis-сессии

DAMU_REDIS_SESSION=1 и, по текущей реализации, DAMU_DISABLE_DB_USER_SESSION должен оставаться не равным 1, иначе UserId() вернет пользователя до RedisCheckUserSession().

Только cookie без server-side check

При DAMU_DISABLE_DB_USER_SESSION=1 функция UserId() после чтения user_id из cookie сразу возвращает его. Это обходит и DB-проверку, и Redis-проверку в данном коде.

Сессии и cookie

DAMUCRM_SALT

Секретная соль для CookieStore; в новом фрагменте инициализации является обязательной переменной запуска.

Go #1: 40 · новый main: обязательная проверка при init()
ТипСтрока / секрет
По умолчаниюНет безопасного значения: пустое приводит к panic в показанном init()
Распознаваемые значенияПроизвольная строка

Как используется

Значение добавляется к результату SessionKey(), после чего итоговая строка преобразуется в []byte и передается в sessions.NewCookieStore(). Таким образом, переменная влияет на криптографический ключ, которым защищается cookie-сессия.

Фактическое поведение

В исходнике CookieStore значение добавляется к SessionKey(). В новом фрагменте запуска дополнительно выполняется проверка: если DAMUCRM_SALT пуст, вызывается panic(errors.New("DAMUCRM_SALT not defined")). То есть для этой сборки переменная фактически обязательна. Изменение соли на работающей системе также меняет ключ CookieStore и инвалидирует ранее выпущенные cookie.

Рекомендация: В production задавать стабильное непредсказуемое секретное значение и хранить его как secret. Не менять без необходимости, если не требуется принудительная инвалидизация существующих cookie.

ТипФлаг
По умолчаниюНесколько DB-сессий запрещены
Распознаваемые значения1 — не удалять предыдущие DB-сессии пользователя

Как используется

Если серверные DB-сессии включены и переменная НЕ равна 1, при логине выполняется delete from user_session where user_id=?. Это удаляет предыдущие DB-сессии пользователя. При 1 удаление не выполняется.

DAMU_DISABLE_DB_USER_SESSION

Отключает запись/проверку серверной пользовательской сессии через таблицу user_session.

Go #1: 233-250, 308-336, 482-504 · Go #2: 2701-2739
ТипФлаг
По умолчаниюDB user_session используется
Распознаваемые значения1 — отключить основную DB-логику user_session

Как используется

При 1 в LoginEvent() пропускается очистка старых DB-сессий и, если Redis не выбран, не выполняется вставка новой записи user_session. В UserId() после чтения user_id из cookie код сразу возвращает его и не выполняет дальнейшую серверную проверку сессии.

Фактическое поведение

Критически важно: в UserId() проверка этого флага стоит ДО ветки DAMU_REDIS_SESSION. Поэтому комбинация DAMU_DISABLE_DB_USER_SESSION=1 + DAMU_REDIS_SESSION=1 приводит к раннему return res и RedisCheckUserSession() не вызывается. При этом LoginEvent() все равно может записать сессию в Redis. Это асимметричное поведение текущего кода.

Дополнение из Lua API. В LuaExtendSession(), если Redis не включен и DAMU_DISABLE_DB_USER_SESSION=1, проверка срока действия и UPDATE поля last_active_at в таблице user_session полностью пропускаются. Функция возвращает успешный результат без обращения к DB-сессии.
Рекомендация: Если Redis должен использоваться именно для серверной валидации сессии, по текущей реализации НЕ устанавливать DAMU_DISABLE_DB_USER_SESSION=1, иначе проверка Redis в UserId() будет обойдена. Этот участок стоит отдельно пересмотреть при рефакторинге.

Переключает хранение/проверку пользовательских сессий с DB-ветки на Redis-ветку.

Go #1: 306-336, 490-503, 655-668 · Go #2: 2663-2701
ТипФлаг
По умолчаниюRedis-сессии выключены

Как используется

После успешного логина при 1 вызывается RedisSetUserSession(anonymousSessionID, user_id, x_real_ip). При проверке пользователя вызывается RedisCheckUserSession(). При logout вызывается RedisDeleteUserSession(). Когда флаг не равен 1, используется таблица user_session.

В DB-режиме код считает время от last_active_at и отклоняет сессию, если прошло более 600 секунд. В Redis-режиме детали TTL/продления не видны в этом файле и зависят от реализации функций Redis*UserSession. Также см. важное взаимодействие с DAMU_DISABLE_DB_USER_SESSION.

Флаг также управляет обслуживанием сессий из Lua: LuaDeleteExpiredSessions() при значении 1 вызывает RedisDeleteExpiredSessions() вместо DELETE из таблицы user_session; LuaExtendSession() проверяет сессию через RedisCheckUserSession() и затем заново вызывает RedisSetUserSession(), фактически обновляя Redis-сессию.
Рекомендация: Для Redis-режима установить DAMU_REDIS_SESSION=1, но по текущему коду оставить DAMU_DISABLE_DB_USER_SESSION отличным от 1, чтобы UserId() действительно дошел до проверки Redis.

ТипФлаг
По умолчаниюЗапись login_logs включена

Как используется

В LoginEvent() блок INSERT в login_logs выполняется только если значение НЕ равно 1. В DoLoginLog() при 1 функция сразу возвращается.

Фактическое поведение

DAMU_CRON_PG_TRY_ADVISORY_LOCK

Добавляет PostgreSQL advisory lock для защиты Cron-задания от одновременного выполнения.

Go #2: 3006-3014, 3039-3043
ТипФлаг
По умолчаниюPostgreSQL advisory lock выключен
Распознаваемые значения1 — включить механизм pg_try_advisory_lock()

Как используется

Перед запуском Cron-кода выполняется pg_try_advisory_lock(CronTabId). Если SQL-запрос успешно выполнен, но lock получить не удалось, задача пропускается с предупреждением already running. Подставляется после tcp(host:port)/. Поэтому фактически код трактует OPENSHIFT_APP_NAME не просто как имя приложения, а как имя MySQL database/schema в DSN.

Фактическое поведение

При PostgreSQL или Oracle весь собранный MySQL DSN заменяется значением CRM_DB_CONN_STR, и эта переменная в показанной ветке больше не влияет на подключение.

Рекомендация: Если исторически имя OpenShift-приложения и имя БД расходятся, это место кода стоит учитывать при миграциях: переменная здесь имеет именно DB-смысл.

OPENSHIFT_GO_IP

IP/host, который Lua API возвращает как адрес HTTP-listener.

Go #2: LuaGetHTTPListenHostPort()
ТипСтрока
По умолчаниюПустая строка
ИспользованиеOPENSHIFT_GO_IP + ":" + OPENSHIFT_GO_PORT

Как используется

Lua-функция GetHTTPListenHostPort() не открывает сокет и не валидирует адрес. Она просто возвращает конкатенацию двух переменных окружения.

Фактическое поведение

Если IP не задан, но порт задан, результат будет вида :8080. Если не заданы обе переменные, результат будет просто :.

Рекомендация: Задавать адрес, который соответствует реальной модели прослушивания приложения, например 0.0.0.0 внутри контейнера либо конкретный bind IP, если это требуется архитектурой.

OPENSHIFT_GO_PORT

Порт HTTP-сервиса, доступный Lua API и стартовому диагностическому логу.

Go #2: LuaGetHTTPListenHostPort(); main/init(): startup log
ТипСтроковое представление порта
По умолчаниюПустая строка
Пример8080

Как используется

Во втором исходнике значение объединяется с OPENSHIFT_GO_IP и возвращается в Lua. В дополнительном main/init() оно также подставляется в стартовое сообщение log.Printf(... port %s).

Фактическое поведение

В показанных местах переменная не преобразуется в число и сама по себе не запускает HTTP-listener. Это строковое конфигурационное значение, которое другие части проекта могут использовать дополнительно.

Рекомендация: Держать синхронизированной с реальным портом, который слушает HTTP-сервер и который опубликован Service/Ingress или контейнерной конфигурацией.
