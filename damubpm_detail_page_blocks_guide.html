1. Модель страницы

Страница — это дерево контейнеров. pages_ui_blocks хранит сами контейнеры, а pages_ui_blocks_n — содержимое и связи между ними.

pages └── pages_ui_blocks └── pages_ui_blocks_n ├── attr ├── block ├── tp ├── html ├── logic └── ui_component
Критически важно: узел типа block — это не дочерний блок как запись. Это элемент родительского блока, который ссылается на другую запись pages_ui_blocks.
СлойРольПример
pagesОбщий шаблон страницы и параметрыpagesdetails
pages_ui_blocksКонтейнер, секция, вкладка, TabViewtabview, tabview_tab
pages_ui_blocks_nУзел внутри блокаattr, block, tp
ui_block_tplHTML-шаблон блокаdefault_page

В текущем pagesdetails используются block, attr, tp и logic.

3. Реальный пример: `pagesdetails`

Корень страницы — default_page. В него элементом block подключён TabView, затем каждая вкладка подключается отдельным узлом типа block.

pagesdetails └── default_page pagesdetails_udsdsad ├── [logic] pages_18153 └── [block] └── TabView ├── [block nn=50] → tabview_tab «Информация» │ └── default_page │ ├── [attr] code │ ├── [attr] entity_id │ ├── [attr] module_id │ ├── [attr] db_template │ ├── [attr] title │ ├── [attr] page_type_id │ ├── [attr] url │ └── [attr] is_auto ├── [block nn=100] → tabview_tab «Логика» │ └── default_page │ └── [attr] angular_json ├── [block nn=200] → tabview_tab «HTML» │ └── default_page │ └── [attr] angular_template └── [block nn=300] → tabview_tab «Custom Blocks» └── [tp] page_cus_blocks
Полезный паттерн: TabView → tabview_tab → default_page → attr/tp. Он хорошо разделяет навигацию, вкладку и раскладку содержимого.

4. Как выполняется генерация

genPages(entity_id)→Detail(page_id, pages_for_gen_ng)→ui_blocks / ui_attrs / table_parts→ParseTemplate→pages.angular_*

Выбор страниц

Берутся страницы сущности с is_auto=1.

Контекст генерации

Для каждой страницы вызывается Detail pages_for_gen_ng.

Подготовка блоков и полей

Формируются ui_blocks, ui_blocks2, ui_attrs, table_parts и связанные наборы.

Параметры

Добавляются component params, table part params, page params и custom blocks.

ParseTemplate

Шаблоны страницы и вложенных блоков превращаются в итоговый HTML/JS.

Сохранение

Результат записывается в pages.angular_template и pages.angular_json.

Не редактируйте результат как источник. У страницы is_auto=1 следующая генерация может перезаписать ручные изменения в angular_template и angular_json.

5. Как рендерится блок

Корневые блоки

ui_blocks содержит блоки страницы, которые не подключены как дочерние через узел типа block. Связи дочерних блоков попадают в ui_blocks2.

Автоматический шаблон блока

pages_ui_blocks.is_auto = 1 → ui_block_tpl.angular_template иначе → pages_ui_blocks.angular_template

Рекурсивный обход

renderBlock(block): nodes = nodes of block sorted by nn attr → render field component tp → render table part block→ renderBlock(child block) logic/html/ui_component → render own template

Для рекурсивной обработки полезно хранить множество посещённых блоков и прекращать обход при обнаружении цикла.

Порядок и ширина

Порядок задаётся nn. Для ширины действует приоритет размещения элемента, затем ширины атрибута, затем default CSS-класс.

6. Рецепт новой detail-страницы

Страница

Привязать страницу к сущности, выбрать detail template, включить is_auto=1, задать code и URL.

Корневой контейнер

Создать default_page либо другой корневой UI block.

TabView при необходимости

Создать блок с template tabview и подключить его в корень узлом типа block.

Вкладки

Для каждой вкладки создать tabview_tab, заполнить header_title и подключить к TabView через block.

Содержимое вкладок

Обычно добавить внутрь вкладки default_page, а в него элементы attr и/или tp.

Порядок

Явно заполнить nn, при необходимости переопределить ширину конкретного элемента.

Генерация

Запустить genPages(entity_id, user_id). Важно: передаётся ID сущности.

Проверка

Проверить HTML/JS, вкладки, поля, readonly/required, табличные части и повторную генерацию.

7. Диагностика структуры SQL

Запрос ниже даёт плоский список блоков и узлов, из которого дерево строится по parent_block_code → child_block_code.

select p.code as page_code, b.code as parent_block_code, ubt.code as block_tpl_code, b.header_title, n.code as element_code, nt.code as element_type, n.nn, ea.code as attr_code, tp.code as table_part_code, cb.code as child_block_code from pages p join pages_ui_blocks b on b.pages_id = p.id left join ui_block_tpl ubt on ubt.id = b.ui_block_tpl_id left join pages_ui_blocks_n n on n.pages_ui_blocks_id = b.id left join pages_ui_blocks_n_t nt on nt.id = n.t_id left join entity_attrs ea on ea.id = n.attr_id left join table_parts tp on tp.id = n.tp_id left join pages_ui_blocks cb on cb.id = n.block_id where p.code = 'pagesdetails' order by coalesce(b.nn,b.id), coalesce(n.nn,n.id);

8. Алгоритм для ИИ/автоматизации

1. Найти страницу и проверить is_auto.
2. Загрузить все блоки страницы.
3. Загрузить все элементы блоков.
4. Разделить элементы по типам.
5. Для block определить child block.
6. Найти блоки, не используемые как child — корни.
7. Построить adjacency map parent → nodes.
8. Сортировать каждый список по nn.
9. Рекурсивно построить дерево.
10. Контролировать циклы.
11. После изменения — генерация по entity_id.
12. Проверить сгенерированный результат.

9. Типовые ошибки

Блок создан, но не отображается
Проверьте принадлежность странице, связь через узел block, корневой статус, шаблон, is_auto блока и ng_if.
Вкладка есть, но пустая
Внутри вкладки должен быть attr, tp или дочерний блок, обычно default_page.
Поле есть в сущности, но не видно
Проверьте узел attr, правильный атрибут, ng_if, hide-field, компонент и результат генерации.
Порядок «плавает»
Явно задайте nn у блоков и элементов.
После генерации пропали ручные HTML-изменения
Для is_auto=1 правьте метаданные, UI block template или page template, а не итоговый HTML/JS.
Рекурсивное зацикливание
Проверьте цепочку child blocks. Связь вида A → B → A недопустима.
