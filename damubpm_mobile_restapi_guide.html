2. Каталог endpoint’ов

GET / POST / PUT / OPTIONSdynamic

Универсальный Lua REST-сервис

Главное адресное пространство пользовательских REST-сервисов DamuBPM. Значение <code> определяет конечный URL сервиса.

Запрос / вход

request.input · request.input_raw · request.get · request.header · request.user_id · request.lang · request.method · request.host · request.RemoteAddr

Ответ / выход

output · http_response_code · header

Важно

  • GET-параметры читаются из request.get.
  • JSON body читается из request.input.
  • Для POST/PUT можно использовать ?async=1.
  • Настройка no_parallel=1 запрещает параллельный запуск одного сервиса.
  • Поддерживаются пользовательские response headers и CORS-настройки.

Пример JSON ответа

{
  "success": true,
  "data": {
    "id": 123,
    "title": "Test"
  }
}
Точная форма зависит от Lua-кода сервиса, потому что поле output формируется самим сервисом.

Запуск BPM-процесса

Запускает BPM-процесс по processCode и передаёт входные переменные.

Запрос / вход

{"processCode":"process_code","input":{"id":125,"title":"Заявка №125"}}

Ответ / выход

{"ok":true,"instance":"INSTANCE-UUID","task":"TASK-UUID","errorText":"","output":{},"instanceIsFinished":false}

Важно

  • Запуск зависит от прав пользователя или публичности процесса.
  • Сохраняйте task, если процесс остановился на ожидающей задаче.
  • instance — UUID экземпляра процесса.

Пример JSON ответа

{
  "ok": true,
  "instance": "INSTANCE-UUID",
  "task": "TASK-UUID",
  "errorText": "",
  "output": {},
  "instanceIsFinished": false
}
Структура подтверждена BPM-справочником.
POSTfixed

Завершение UserTask по task

Рекомендуемый REST-контракт для продолжения пользовательской задачи по UUID task.

Запрос / вход

{"task":"TASK-UUID","input":{"decision":"approve","comment":"Согласовано"}}

Ответ / выход

ok · errorVars · errorText · task · output · instance · instanceIsFinished

Важно

  • Стройте новый код вокруг task + input.
  • task является главным идентификатором текущей ожидающей задачи.
  • Не передавайте пустой input, если точка требует обязательные переменные.

Пример JSON ответа

{
  "ok": true,
  "errorVars": {},
  "errorText": "",
  "task": "NEXT-TASK-UUID",
  "output": {},
  "instance": "INSTANCE-UUID",
  "instanceIsFinished": false
}
Набор полей подтверждён источником; конкретные значения зависят от процесса.

POSTrelated

Изменение данных сущностей

Связанный API DamuBPM для insert/delete сущностей. Путь не находится под /restapi, но важен для мобильного CRUD.

Запрос / вход

{"items":[{"table_name":"entity_code","action":"insert","values":[{"sys$uuid":"uuid","id":0}]}]}

Ответ / выход

error · error_text · items · last_insert_id (для insert-сценария)

Важно

  • В приложенных знаниях подтверждены action=insert и action=delete.
  • Для delete values содержит объекты вида {id: 10}.
  • Не добавляйте другие action без отдельного подтверждения серверного контракта.

Пример JSON ответа

{
  "error": 0,
  "error_text": "",
  "items": [],
  "last_insert_id": 123
}
Поля error/error_text подтверждены CRUD-гайдом. last_insert_id относится к insert-сценарию; состав items зависит от операции.

3. Как устроен `/restapi/services/run/<code>`

Это главное семейство пользовательских REST-сервисов. Код сервиса становится частью URL. Например, api/v1/customer/create → /restapi/services/run/api/v1/customer/create.

Источник данных LuaДля чего использовать
request.inputJSON body как Lua-таблица
request.input_rawИсходное тело запроса
request.getQuery/form параметры
request.headerHTTP headers клиента
request.user_idID текущего пользователя строкой; для числа используйте tonumber()
request.langЯзык
request.methodGET / POST / PUT
request.host, request.RemoteAddrHost и удалённый адрес

Lua-шаблон endpoint’а

-- GET
local id = request.get.id

-- POST/PUT JSON
local input = request.input

-- Headers
local apiKey = request.header["X-Api-Key"]

-- Current user
local userId = tonumber(request.user_id)

-- Response
http_response_code = 200
header = {
  ["X-Service"] = "mobile-api",
  ["Cache-Control"] = "no-store"
}
output = {
  success = true,
  data = {}
}
Async: для POST/PUT можно добавить ?async=1; клиент сразу получает ASYNC OK. no_parallel=1 — настройка сервиса, запрещающая параллельный запуск одного и того же сервиса.

5. Flutter / Dart

Важно: код Flutter ниже — клиентская интеграционная обёртка, созданная для удобства использования подтверждённых HTTP-контрактов. Конкретный механизм авторизации мобильного клиента (Bearer/cookie и т. п.) приложенные MD полностью не описывают, поэтому он оставлен через defaultHeaders.
import 'dart:convert';
import 'package:http/http.dart' as http;

class DamuApiClient {
  DamuApiClient({
    required this.baseUrl,
    this.defaultHeaders = const {},
  });

  final String baseUrl;
  final Map<String, String> defaultHeaders;

  Uri uri(String path, [Map<String, dynamic>? query]) {
    final base = Uri.parse('$baseUrl$path');
    if (query == null || query.isEmpty) return base;
    return base.replace(
      queryParameters: query.map(
        (k, v) => MapEntry(k, v?.toString() ?? ''),
      ),
    );
  }

  Future<Map<String, dynamic>> getJson(
    String path, {
    Map<String, dynamic>? query,
    Map<String, String>? headers,
  }) async {
    final response = await http.get(
      uri(path, query),
      headers: {...defaultHeaders, ...?headers},
    );
    return _decode(response);
  }

  Future<Map<String, dynamic>> postJson(
    String path,
    Object body, {
    Map<String, dynamic>? query,
    Map<String, String>? headers,
  }) async {
    final response = await http.post(
      uri(path, query),
      headers: {
        'Content-Type': 'application/json',
        ...defaultHeaders,
        ...?headers,
      },
      body: jsonEncode(body),
    );
    return _decode(response);
  }

  Future<Map<String, dynamic>> putJson(
    String path,
    Object body, {
    Map<String, dynamic>? query,
    Map<String, String>? headers,
  }) async {
    final response = await http.put(
      uri(path, query),
      headers: {
        'Content-Type': 'application/json',
        ...defaultHeaders,
        ...?headers,
      },
      body: jsonEncode(body),
    );
    return _decode(response);
  }

  Map<String, dynamic> _decode(http.Response response) {
    final dynamic decoded = response.body.isEmpty
        ? <String, dynamic>{}
        : jsonDecode(response.body);

    if (response.statusCode < 200 || response.statusCode >= 300) {
      throw DamuApiException(
        statusCode: response.statusCode,
        body: decoded,
      );
    }

    if (decoded is Map<String, dynamic>) return decoded;
    return {'data': decoded};
  }
}

  DamuApiException({required this.statusCode, required this.body});
  final int statusCode;
  final Object body;

  @override
  String toString() => 'DamuApiException($statusCode): $body';
}

class BpmStartResult {
  const BpmStartResult({
    required this.ok,
    required this.instance,
    required this.task,
    required this.errorText,
    required this.output,
    required this.instanceIsFinished,
  });

  final bool ok;
  final String? instance;
  final String? task;
  final String errorText;
  final Map<String, dynamic> output;
  final bool instanceIsFinished;

  factory BpmStartResult.fromJson(Map<String, dynamic> json) {
    return BpmStartResult(
      ok: json['ok'] == true,
      instance: json['instance'] as String?,
      task: json['task'] as String?,
      errorText: (json['errorText'] ?? '').toString(),
      output: (json['output'] as Map?)?.cast<String, dynamic>() ?? {},
      instanceIsFinished: json['instanceIsFinished'] == true,
    );
  }
}

6. Мобильный BPM-flow

  1. POST /restapi/bpms/start → получить instance, task, output.
  2. Если instanceIsFinished == true — процесс завершён.
  3. Если есть task — при необходимости получить форму через ShowUserTaskForm/:task.
  4. Показать пользователю нативный Flutter UI.
  5. Отправить результат через POST /restapi/bpms/runUserTaskByTask/ с task + input.
  6. Сохранить новую task или обработать instanceIsFinished.
В источнике отдельно подчёркнуто: для нового кода лучше строить контракт вокруг UUID task, а не старых схем с pointCode или лишними полями.

8. Mobile checklist

  • Используйте HTTPS для production mobile API.
  • Не храните секретный API key прямо в исходниках Flutter, если он даёт привилегированный доступ.
  • Проверяйте response.statusCode до разбора business payload.
  • Не считайте task просто строкой навигации — это идентификатор текущей BPM-задачи.
  • Для Lua REST валидируйте обязательные поля request.input и query-параметры.
  • Для тяжёлых интеграционных сервисов рассмотрите no_parallel=1; для POST/PUT поддерживается ?async=1.
  • Настройте CORS только если API будет вызываться браузерным клиентом; нативный Flutter-клиент не зависит от browser CORS-модели.

Пункты про HTTPS, безопасное хранение секретов и поведение нативного Flutter относительно CORS — общие рекомендации мобильной интеграции, а не отдельные серверные контракты из MD.
