1. URL и методы

Код сервиса становится частью URL:

Шаблон URL
/restapi/services/run/<code>

GETПолучение данных

GET /restapi/services/run/customer/get?id=123

POSTСоздание / действие

POST /restapi/services/run/customer/create

PUTИзменение

PUT /restapi/services/run/customer/update

OPTIONS

Используется для предварительных запросов браузера и правил CORS.

Рекомендация: версионируй свои сервисы кодом, например api/v1/customer/create, api/v1/customer/get.

3. Как формируется ответ

output

Главная переменная ответа. Может быть строкой или Lua-таблицей.

http_response_code

HTTP-статус: 200, 201, 400, 401, 404, 409 и т. д.

header

Таблица дополнительных HTTP-заголовков ответа.

Базовый JSON-ответ
http_response_code = 200

header = {
  ["X-Service"] = "customer"
}

output = {
  success = true,
  data = {
    id = 123,
    title = "Test"
  }
}
Для чистого REST-ответа удобно использовать настройку cut_status_info = 1. Тогда наружу возвращается непосредственно output.

8. Авторизация и сессия

Публичный endpoint

Используй только там, где сервис действительно должен вызываться без пользовательской сессии.

is_public = 1

Авторизованный endpoint

Для приватных сервисов используй авторизованный режим и при необходимости ограничения по ролям.

request.user_id позволяет получить текущего пользователя.

Встроенные функции сессии

ФункцияНазначение
Login(user_id, deviceToken)Установить пользовательскую сессию
LoginAs(user_id, last_user_id, deviceToken)Войти как другой пользователь с сохранением предыдущего ID
SendEmailOTP(email)Создать и отправить OTP на email
CheckOTP(otp)Проверить OTP текущей сессии
Важно: точный набор остальных функций платформы зависит от зарегистрированного Lua API в конкретной сборке. В этом справочнике не используются не подтверждённые имена функций.

9. Async и no_parallel

Асинхронный запуск

Для POST/PUT можно добавить query-параметр:

?async=1

Запрос сразу получает ответ ASYNC OK, а сервис запускается отдельно.

Запрет параллельного выполнения

При no_parallel = 1 один и тот же сервис не будет одновременно выполняться несколько раз. Если он уже запущен, возвращается служебная ошибка с кодом 7 и сообщением Service already started.

Где использовать

Импорт, синхронизация, генерация больших отчётов, перерасчёты, интеграционные процедуры.

Где не нужен

Обычные короткие GET/POST-запросы, которые безопасно выполняются параллельно.

10. Заголовки и CORS

Есть два уровня заголовков: динамические из Lua через header и настроенные для сервиса HTTP-заголовки.

Lua response headers

header = {
  ["X-Service"] = "customer",
  ["Cache-Control"] = "no-store"
}

output = {success = true}

Подстановка входящего header в настройках

В значении настроенного заголовка можно использовать шаблон входящего header:

Access-Control-Allow-Origin: {{Origin}}
Практика CORS: удобно настроить отдельные headers для нужных HTTP-методов сервиса и обрабатывать OPTIONS тем же набором правил.

11. Рекомендуемые шаблоны

Шаблон 1 — обычный JSON endpoint

Lua
local function fail(status, code, message)
  http_response_code = status
  output = {
    success = false,
    error = {
      code = code,
      message = message
    }
  }
end

local input = request.input

if not input then
  fail(400, "INVALID_BODY", "JSON body required")
  return
end

  success = true,
  data = {}
}

Шаблон 2 — GET с обязательным ID

Lua

  http_response_code = 400
  output = {
    success = false,
    error = "id is required"
  }
  return
end

output = {
  success = true,
  data = {
    id = id
  }
}

Шаблон 3 — приватный POST

Lua
local userId = tonumber(request.user_id)
local input = request.input

if not userId or userId == 0 then
  http_response_code = 401
  output = {success = false, error = "Unauthorized"}
  return

  http_response_code = 400
  output = {success = false, error = "JSON body required"}
  return
end

  success = true,
  user_id = userId,
  data = input
}

Шаблон 4 — API-key

Lua

    error = "Invalid API key"
  }
  return
