Примеры не запускаются автоматически.

Основной сценарий: интерфейс подписывается на события, Lua отправляет уведомление, интерфейс перечитывает необходимые данные через обычный Query или REST. WebSocket используется как канал уведомления, а не как подтверждение сохранения данных.

Граница достоверности. Предоставлены три маршрута, модуль рассылки hAccountChat и реализация Lua-отправителя. Обработчики подключения, чтения и записи сообщений не приложены. Ниже явно отделены подтверждённый контракт, сведения из документации DamuBPM и предлагаемые прикладные примеры. Формат адресных сообщений и правила доступа не выдумываются.

Совпадений нет. Попробуйте другой термин или код ошибки.

01Быстрый старт

Что выбрать

Задача Подход Что проверить заранее
Получать события в существующем JIT-виджете this.websocketService.messages.subscribe(...) Какой маршрут и формат использует сервис в вашей сборке
Проверить конкретный WebSocket-маршрут Нативный new WebSocket(...) Авторизацию и допустимость подключения к этому маршруту
Отправить событие из Lua SendWSAsync(wsServer, path, msg) Доступный внутренний адрес без схемы и действительный путь
Уведомить конкретного пользователя Маршрут /ws/ServeMsgToUser Контракт адресации отсутствует в присланных исходниках
Работать с отдельной комнатой Маршрут /ws/ServeMsgToRoom/:room Правила подписки, отправки и проверки участника комнаты

Последовательность для тестового контура: сначала открыть подписчика и дождаться события open, затем выполнить Lua-отправку, затем проверить получение и разбор сообщения. Успешный возврат из Lua сам по себе не доказывает доставку браузеру.

Минимальный вызов Lua после уточнения адреса:

lua
-- Адрес и порт ниже иллюстративные, замените на адрес своего контура.
local err, code = SendWSAsync(
    "127.0.0.1:8080",
    "/ws/ServeAccountChat",
    JsonToString({
        version = 1,
        type = "demo.ping",
        event_id = UUID(),
        data = { message = "Test event", items = array({}) }
    })
)

if code ~= 0 then
    print("WebSocket send failed", code, err)
else
    print("WebSocket frame written; delivery is not confirmed")
end

SendWSAsync, JsonToString и UUID — существующие API из справочника DamuBPM. Для JSON-массивов используется array({}). Доступность маршрута для такого подключения необходимо подтвердить в вашем контуре. S3, S4

02Маршруты и подключение

Из регистрации маршрутов подтверждены следующие адреса. S1

Путь Зарегистрированные HTTP-методы Что известно Что не установлено
/ws/ServeAccountChat GET, POST Путь направлен в обработчик AccountChat; отдельно предоставлен модуль hAccountChat Авторизация, регистрация соединений, чтение и формат исходящих кадров
/ws/ServeMsgToUser GET, POST Существует отдельный обработчик Как определяется пользователь и как указывается получатель
/ws/ServeMsgToRoom/:room GET, POST В пути есть динамический сегмент room Как создаётся комната, кто может подключаться и кто получает отправку

/ws/... — самостоятельные маршруты. Не добавляйте перед ними /restapi/services/run/.

Регистрация POST не означает, что обычный HTTP POST публикует сообщение. Без реализации обработчика нельзя утверждать, что fetch('/ws/…', {method: 'POST'}) является поддерживаемым способом отправки. Для браузерного WebSocket используйте new WebSocket(...), а для вызова вашего Lua REST-сервиса — отдельный REST API.

Адрес браузера

Пример для приложения на том же хосте, без дополнительного внешнего префикса:

javascript
const url = new URL(window.location.href);
url.protocol = window.location.protocol === 'https:' ? 'wss:' : 'ws:';
url.pathname = '/ws/ServeAccountChat';
url.search = '';
url.hash = '';

const socket = new WebSocket(url.href);

Для HTTPS-страницы используйте wss:. Внешний прокси должен передавать WebSocket-подключение нужному обработчику. Если платформа опубликована под префиксом, в pathname нужен фактический внешний путь. Не запускайте этот пример из локального file://-документа: выполняйте его внутри открытого приложения. Общая механика подключения описана в браузерной документации, а не в присланном модуле DamuBPM. 03Что делает рассылка AccountChat

Подтверждено только для предоставленного модуля hAccountChat. S2

Событие внутри модуля Поведение
Регистрация соединения Соединение добавляется в набор активных
Удаление соединения Соединение исключается, его очередь отправки закрывается
Входящее событие рассылки Одинаковые байты предлагаются каждому зарегистрированному соединению
Очередь соединения не может немедленно принять сообщение Очередь закрывается, соединение исключается из набора

В показанном цикле нет фильтрации по user_id, account_id, room или type. Отправитель также специально не исключается: если его соединение находится в наборе, цикл обрабатывает его наравне с остальными.

Это не доказывает публичность endpoint. Допуск соединений может выполняться в отсутствующем обработчике. Но считать сам показанный модуль механизмом изоляции пользователей, организаций или комнат нельзя.

В модуле нет истории сообщений, подтверждений чтения и восстановления пропущенных событий. Исключение из набора и закрытие очереди не описывают точный код закрытия браузерного соединения: он зависит от отсутствующей части записи.

Практический вывод: через этот канал безопаснее передавать небольшой сигнал обновления без конфиденциальных данных, а сами данные запрашивать через API с проверкой прав.

04Backend Lua: SendWSAsync

Сигнатура

lua
local err, code = SendWSAsync(wsServer, path, msg)

Публичное Lua-имя подтверждено справочником API. Детали транспорта ниже взяты из предоставленной реализации отправителя. S3, S4

Аргумент Передавать Не передавать
wsServer Строку host:port, например 127.0.0.1:8080 Полный URL со схемой ws://, wss://, http:// или https://
path Путь, начинающийся с /, например /ws/ServeAccountChat Полный URL или объект параметров
msg Строку, например результат JsonToString(payload) Lua-таблицу без сериализации

Важное расхождение со справочником: там wsServer назван URL, а отправка — асинхронной. Предоставленная реализация отдельно задаёт схему ws, подключается и записывает сообщение до возврата. Поэтому в этом руководстве используются host:port и фактическое поведение, без обещания фонового выполнения.

Последовательность одного вызова

text
Lua → новое ws-подключение → один бинарный кадр → закрытие подключения → возврат err, code

Закрытие относится к успешной ветке. В ветке ошибки записи явное закрытие в присланном фрагменте не показано.

Отправитель не читает ответ, не ждёт подтверждения получателя и не сохраняет соединение для следующего вызова. В реализации не передаются пользовательские заголовки, Cookie или Authorization. Тайм-аут не настраивается аргументами функции.

Возвращаемые значения

code Значение err Значение результата
0 Пустая строка Подключение установлено, операция записи кадра завершилась без ошибки
2 err LuaSendWSAsync Не прошла проверка преобразования аргумента сообщения
3 Текст ошибки подключения Ошибка адреса, сети или установления WebSocket-соединения
42 Текст ошибки записи Не удалось записать бинарное сообщение

В исходнике итоговая проверка преобразования относится к последнему аргументу, поэтому код 2 нельзя считать полноценной валидацией всех трёх аргументов. Передавайте строки явно. Тестовые и недостижимые ветки не включены в рабочий контракт.

code == 0 не равно «сообщение доставлено», «получатель онлайн» или «пользователь прочитал сообщение». Принимающая сторона могла отвергнуть данные после записи, получателей могло не быть, соединение могло оборваться позднее.

Ограничение ws / wss

Схема отправителя жёстко задана как ws. Передача wss:// в первом аргументе не включает TLS. Допустимая схема развёртывания — браузер подключается по wss к внешнему защищённому адресу, а Lua использует отдельно разрешённый внутренний ws-адрес. Его доступность и контроль доступа должны быть настроены в инфраструктуре; это не готовая возможность, подтверждённая исходниками.

path используется именно как компонент пути, не как конструктор query string. Не рассчитывайте на передачу токена через path .. '?token=...': отдельной настройки query string или заголовков здесь нет.

Объекты и массивы

lua
local payload = {
    version = 1,
    type = "demo.ping",
    event_id = UUID(),
    data = {
        message = "Test event",
        items = array({
            { id = 101, title = "Demo A" },
            { id = 102, title = "Demo B" }
        }),
        errors = array({})
    }
}

local message = JsonToString(payload)

data — объект. items и errors — массивы, включая пустой массив []. Не собирайте JSON конкатенацией строк и не используйте текстовые замены для экранирования данных.

05Формат прикладного события

Предлагаемое соглашение примеров, не встроенный протокол DamuBPM. В предоставленном модуле рассылки нет разбора JSON. Возможные требования отсутствующих обработчиков этим примером не заменяются.

json
{
  "version": 1,
  "type": "demo.ping",
  "event_id": "0a783932-f310-45cc-89c9-af47a02f4a18",
  "data": {
    "message": "Test event",
    "items": []
  }
}
Поле Назначение в примерах
version Версия вашего формата; здесь 1
type Тип прикладного события; здесь demo.ping
event_id Стабильный идентификатор события для устранения повторов
data Небольшой JSON-объект с содержимым

Один JSON-объект на одно WebSocket-сообщение — соглашение этих примеров. Перед внедрением проверьте, не объединяет ли фактический серверный writer несколько событий и не добавляет ли собственную оболочку. Не делите поток по переводам строк без документированного формата.

Добавление полей user_id, room или recipient само по себе не создаёт адресную доставку. Клиентская фильтрация типа события нужна для интерфейса, но не является контролем доступа.

06Frontend: минимальный браузерный клиент

Фрагмент предназначен для консоли тестового приложения. Он не выполняется автоматически при открытии этой документации.

javascript
const url = new URL(window.location.href);
url.protocol = window.location.protocol === 'https:' ? 'wss:' : 'ws:';
url.pathname = '/ws/ServeAccountChat';
url.search = '';
url.hash = '';

const socket = new WebSocket(url.href);
socket.binaryType = 'arraybuffer';
const decoder = new TextDecoder('utf-8', { fatal: true });

socket.onopen = () => console.log('WebSocket: connected');
socket.onerror = () => console.warn('WebSocket: inspect Network / WS');
socket.onclose = event => {
    console.log('WebSocket: closed', event.code, event.reason);
};

socket.onmessage = event => {
    try {
        const text = typeof event.data === 'string'
            ? event.data
            : decoder.decode(event.data);
        const message = JSON.parse(text);
        console.log('WebSocket event:', message);
    } catch (error) {
        console.warn('Unsupported frame or invalid JSON', error);
    }
};

// После завершения проверки:
// socket.close(1000, 'test finished');

Отправитель Lua посылает бинарный кадр на сервер. Но тип кадра, который сервер отправляет браузеру, по модулю рассылки не определяется. Поэтому пример принимает как строку, так и ArrayBuffer. Значение binaryType по умолчанию — blob; прямой JSON.parse(event.data) для такого случая не подходит. binaryType управляет представлением получаемых бинарных данных, а не переводит исходящую отправку в бинарный режим. S2, S3, B2

Отправка из браузера

Использовать только после подтверждения, что выбранный обработчик разрешает клиенту публиковать такой формат:

javascript
function sendDemo(socket, payload, binary = false) {
    if (socket.readyState !== WebSocket.OPEN) {
        throw new Error('WebSocket is not open');
    }
    const bytes = new TextEncoder().encode(JSON.stringify(payload));
    if (bytes.byteLength > 65536) {
        throw new Error('Example message limit exceeded');
    }
    if (socket.bufferedAmount + bytes.byteLength > 262144) {
        throw new Error('Example output buffer limit exceeded');
    }
    socket.send(binary ? bytes : new TextDecoder().decode(bytes));
}

send() со строкой отправляет текст; с Uint8Array — бинарные данные. Вызов до OPEN недопустим. Возврат из send() означает постановку данных на отправку, а не подтверждение получателя. Лимиты 64 КиБ на сообщение и 256 КиБ на исходящий буфер — выбранные ограничения примера, не лимиты DamuBPM. B3

07Полный JIT-пример: собственное подключение

Этот вариант подходит для проверки конкретного маршрута. Он создаёт одно собственное соединение на экземпляр виджета. Если проект уже получает нужные события через websocketService, сначала используйте вариант из следующего раздела, чтобы не создавать лишние подключения.

Пример показывает новые события demo.ping, выполняет ограниченное переподключение, последовательно разбирает сообщения и освобождает ресурсы при уходе со страницы. Кнопка отправки вызывает ваш тестовый сервис ws_demo_publish из раздела 09. Ни сервис, ни виджет этим документом не публикуются.

Logic / JavaScript

Вставляется в поле логики JIT, не в обычный <script> статической страницы. Конструкция класса соответствует документации виджетов DamuBPM. S5

javascript
const vm = this;

return class GenClass extends vm.constructor {
    wsPath = '/ws/ServeAccountChat';
    status = 'Не подключено';
    notice = '';
    publishResult = '';
    publishing = false;
    events = [];

    ngOnInit() {
        this._alive = true;
        this._socket = null;
        this._retry = 0;
        this._retryTimer = null;
        this._openTimer = null;
        this._stableTimer = null;
        this._publishSub = null;
        this._seen = new Set();
        this._decoder = new TextDecoder('utf-8', { fatal: true });
        this.connect();
    }

    isCurrent(socket) {
        return this._alive && this._socket === socket;
    }

    clearConnectionTimers() {
        clearTimeout(this._openTimer);
        clearTimeout(this._stableTimer);
        this._openTimer = null;
        this._stableTimer = null;
    }

    connect() {
        if (!this._alive || this._socket) return;
        clearTimeout(this._retryTimer);
        this._retryTimer = null;

        let socket;
        try {
            const url = new URL(window.location.href);
            if (!['http:', 'https:'].includes(url.protocol)) {
                throw new Error('Откройте виджет внутри приложения');
            }
            url.protocol = url.protocol === 'https:' ? 'wss:' : 'ws:';
            url.pathname = this.wsPath;
            url.search = '';
            url.hash = '';
            socket = new WebSocket(url.href);
        } catch (error) {
            this.status = 'Ошибка адреса';
            this.notice = String(error.message || error);
            return;
        }

        this._socket = socket;
        socket.binaryType = 'arraybuffer';
        this.status = 'Подключение';
        let pending = 0;
        let chain = Promise.resolve();

        this._openTimer = setTimeout(() => {
            if (this.isCurrent(socket) &&
                socket.readyState === WebSocket.CONNECTING) {
                this.notice = 'Истекло время подключения';
                socket.close();
            }
        }, 10000);

        socket.onopen = () => {
            if (!this.isCurrent(socket)) return;
            clearTimeout(this._openTimer);
            this._openTimer = null;
            this.status = 'Подключено';
            this.notice = 'Показываются только новые события. ' +
                'Рабочие данные после подключения нужно перечитать через API.';
            this._stableTimer = setTimeout(() => {
                if (this.isCurrent(socket)) this._retry = 0;
            }, 30000);
        };

        socket.onmessage = event => {
            if (!this.isCurrent(socket)) return;
            if (pending >= 64) {
                this.notice = 'Очередь обработки переполнена; нужна синхронизация';
                socket.close(1000, 'receive queue overflow');
                return;
            }
            const raw = event.data;
            pending++;
            chain = chain.then(async () => {
                if (!this.isCurrent(socket)) return;
                const text = await this.decodeFrame(raw);
                if (!this.isCurrent(socket)) return;
                const msg = JSON.parse(text);
                if (!msg || typeof msg !== 'object' || Array.isArray(msg)) return;
                if (msg.version !== 1 || msg.type !== 'demo.ping') return;
                if (typeof msg.event_id !== 'string' ||
                    !msg.event_id || msg.event_id.length > 128) return;
                if (!msg.data || typeof msg.data !== 'object' ||
                    Array.isArray(msg.data)) return;
                if (this._seen.has(msg.event_id)) return;

                this._seen.add(msg.event_id);
                if (this._seen.size > 1000) {
                    this._seen.delete(this._seen.values().next().value);
                }
                const preview = typeof msg.data.message === 'string'
                    ? msg.data.message
                    : JSON.stringify(msg.data);
                this.events = [{
                    id: msg.event_id,
                    type: msg.type,
                    preview: preview.slice(0, 200)
                }, ...this.events].slice(0, 100);
            }).catch(error => {
                if (this.isCurrent(socket)) {
                    this.notice = 'Сообщение пропущено: ' +
                        String(error.message || error);
                }
            }).finally(() => { pending--; });
        };

        socket.onerror = () => {
            if (this.isCurrent(socket)) {
                this.notice = 'Ошибка WebSocket. Проверьте Network / WS.';
            }
        };

        socket.onclose = event => {
            if (!this.isCurrent(socket)) return;
            this.clearConnectionTimers();
            this._socket = null;
            this.status = 'Отключено';
            this.notice = 'Соединение закрыто, код ' + event.code;
            if ([1003, 1007, 1008, 1009].includes(event.code)) {
                this.notice += '. Проверьте формат, доступ и размер сообщения.';
                return;
            }
            this.scheduleReconnect();
        };
    }

    async decodeFrame(raw) {
        const limit = 65536;
        if (typeof raw === 'string') {
            if (new TextEncoder().encode(raw).byteLength > limit) {
                throw new Error('Сообщение больше 64 КиБ');
            }
            return raw;
        }
        if (raw instanceof Blob) {
            if (raw.size > limit) throw new Error('Сообщение больше 64 КиБ');
            return this._decoder.decode(await raw.arrayBuffer());
        }
        if (raw instanceof ArrayBuffer) {
            if (raw.byteLength > limit) throw new Error('Сообщение больше 64 КиБ');
            return this._decoder.decode(raw);
        }
        throw new Error('Неизвестный тип кадра');
    }

    scheduleReconnect() {
        if (!this._alive || this._retryTimer !== null) return;
        if (this._retry >= 8) {
            this.status = 'Повторы остановлены';
            this.notice = 'Проверьте подключение и нажмите «Подключить».';
            return;
        }
        const delay = Math.min(30000,
            500 * Math.pow(2, this._retry) + Math.random() * 300);
        this._retry++;
        this.status = 'Ожидание повтора ' + this._retry;
        this._retryTimer = setTimeout(() => {
            this._retryTimer = null;
            this.connect();
        }, delay);
    }

    retryNow() {
        if (!this._alive || this._socket) return;
        this._retry = 0;
        this.connect();
    }

    publishFromLua() {
        if (this.publishing) return;
        if (!this._socket || this._socket.readyState !== WebSocket.OPEN) {
            this.publishResult = 'Сначала дождитесь подключения подписчика';
            return;
        }
        this.publishing = true;
        this.publishResult = '';
        this._publishSub = this.dbQueryService.restapiPost(
            'ws_demo_publish',
            {},
            true
        ).subscribe({
            next: resp => {
                if (!this._alive) return;
                this.publishing = false;
                this.publishResult = resp && resp.success
                    ? 'Lua: кадр записан. Подтверждение доставки отсутствует.'
                    : 'Lua: отправка не выполнена';
            },
            error: () => {
                if (!this._alive) return;
                this.publishing = false;
                this.publishResult = 'Ошибка REST. Проверьте ответ и журнал сервера.';
            }
        });
    }

    ngOnDestroy() {
        this._alive = false;
        clearTimeout(this._retryTimer);
        this.clearConnectionTimers();
        if (this._publishSub) this._publishSub.unsubscribe();
        const socket = this._socket;
        this._socket = null;
        if (socket) {
            socket.onopen = null;
            socket.onmessage = null;
            socket.onerror = null;
            socket.onclose = null;
            socket.close(1000, 'widget destroyed');
        }
    }
};

08JIT: встроенный websocketService

Документация виджетов подтверждает поток this.websocketService.messages и отписку через unsubscribe(). Она приводит пример проверки msg.type === 'url_notification'. Однако маршрут подключения, преобразование кадров, переподключение и жизненный цикл самого сервиса там не раскрыты. S5

Для существующей платформенной интеграции используйте её фактический контракт, а не одновременно собственный socket и сервис для одного и того же события.

javascript
const vm = this;

return class GenClass extends vm.constructor {
    notificationText = 'Ожидание уведомления';

    ngOnInit() {
        this._wsSub = this.websocketService.messages.subscribe(msg => {
            if (!msg || msg.type !== 'url_notification' || !msg.data) return;
            this.notificationText = 'Получено уведомление об обновлении';
            // Здесь вызовите существующий метод чтения данных своего виджета.
        });
    }

    ngOnDestroy() {
        if (this._wsSub) {
            this._wsSub.unsubscribe();
            this._wsSub = null;
        }
    }
};
html
<section class="card">
    <h3>Уведомления платформы</h3>
    <p role="status">{{ notificationText }}</p>
</section>

В этом варианте виджет владеет подпиской, но не обязательно общим соединением приложения. Поэтому он отписывается от потока, а не вызывает вымышленный метод закрытия websocketService.

url_notification из документации сервиса и demo.ping из нашего примера — разные контракты. Не предполагается, что сервис автоматически получит и обработает demo.ping или что публикация в AccountChat обязательно попадает в его поток.

09Backend: тестовый Lua REST-сервис

Прикладной пример для создания в тестовом контуре, не существующий встроенный сервис. Он публикует только фиксированное обезличенное событие. Бизнес-данные и произвольный адрес назначения от клиента не принимаются.

Сначала ограничьте доступ к тестовому сервису нужной ролью штатными средствами вашего проекта. Флаг авторизации сам по себе не является проверкой бизнес-полномочий.

Настройки

Поле Значение
code ws_demo_publish
only_auth 1
is_public 0
cut_status_info 1
Тип ответа application/json

Вызов: POST /restapi/services/run/ws_demo_publish, JSON body: {}. Поля request, output, http_response_code и перечисленные настройки описаны в руководстве REST API DamuBPM. S6

Lua-код

lua
local WS_SERVER = ""
local WS_PATH = "/ws/ServeAccountChat"

header = {
    ["Cache-Control"] = "no-store"
}

if request.method ~= "POST" then
    header["Allow"] = "POST"
    http_response_code = 405
    output = { success = false, error = "POST_REQUIRED" }
    return
end

local userId = tonumber(request.user_id)
if userId == nil or userId <= 0 then
    http_response_code = 401
    output = { success = false, error = "AUTH_REQUIRED" }
    return
end

if WS_SERVER == "" then
    http_response_code = 500
    output = { success = false, error = "WS_SERVER_NOT_CONFIGURED" }
    return
end

local eventId = UUID()
local payload = {
    version = 1,
    type = "demo.ping",
    event_id = eventId,
    data = {
        message = "Test event from Lua",
        items = array({})
    }
}

local err, code = SendWSAsync(
    WS_SERVER,
    WS_PATH,
    JsonToString(payload)
)

if code ~= 0 then
    print("ws_demo_publish failed", eventId, code, err)
    http_response_code = 502
    output = {
        success = false,
        error = "WS_SEND_FAILED",
        transport_code = code,
        event_id = eventId
    }
    return
end

http_response_code = 200
output = {
    success = true,
    state = "transport_written",
    event_id = eventId,
    transport_code = code,
    delivery_confirmed = false
}

Задайте WS_SERVER вручную, например 127.0.0.1:8080, только если это действительный разрешённый адрес вашего контура. Пустое значение намеренно останавливает пример, чтобы не угадывать инфраструктуру.

Проверка авторизации REST-запроса не передаёт сессию в SendWSAsync: это отдельное исходящее WebSocket-подключение без пользовательских заголовков. Если обработчик требует сессию, вызов может не пройти; не отключайте защиту ради теста.

Вызов с Frontend

Кнопка в полном JIT-примере уже использует этот вызов:

javascript
this.dbQueryService.restapiPost(
    'ws_demo_publish',
    {},
    true
).subscribe({
    next: response => console.log(response),
    error: error => console.warn('REST call failed', error)
});

Третий аргумент true отключает загрузчик DamuBPM. Такой же третий аргумент нужно передавать в this.dbQueryService.restapiGet(...) при чтении данных в обработчике событий.

Ответ state: "transport_written" описывает транспортную запись. Он не сообщает, сколько подписчиков получили событие. Факт получения проверяется отдельно на стороне подписчика по event_id.

10Сообщения пользователю и комнате

Комната: что можно показать достоверно

Из маршрута известен путь с одним параметром room. Такой код правильно формирует URL для отдельного сегмента, но не доказывает наличие подписки, публикации или изоляции участников. S1

javascript
const room = 'demo-room-001';
const path = '/ws/ServeMsgToRoom/' + encodeURIComponent(room);
const url = new URL(window.location.href);
url.protocol = url.protocol === 'https:' ? 'wss:' : 'ws:';
url.pathname = path;
url.search = '';
url.hash = '';

const roomSocket = new WebSocket(url.href);
// Добавьте обработчики, проверку доступа и закрытие по примеру выше.

Для Lua используйте заранее определённый безопасный идентификатор, без произвольных фрагментов URL:

lua
local room = "demo-room-001"
local path = "/ws/ServeMsgToRoom/" .. room

-- Только после подтверждения контракта обработчика комнаты:
-- local err, code = SendWSAsync(wsServer, path, JsonToString(payload))

Переменные wsServer и payload в закомментированном вызове относятся к вашей конфигурации и подтверждённому формату сообщения. Пустой room не соответствует показанному маршруту. Использование / внутри идентификатора требует отдельной проверки маршрутизатора; проще ограничить прикладные room ID буквами ASCII, цифрами, дефисом и подчёркиванием.

Пользователь: чего нельзя заключать из имени

Подтверждён только путь /ws/ServeMsgToUser, без параметра в URL. Нет оснований документировать /ws/ServeMsgToUser/123, ?user_id=123, JSON-поле to или автоматически подставляемую текущую сессию.

Перед рабочей адресной интеграцией нужно установить по обработчику или проверке контура: откуда берётся ID пользователя, кто может отправлять ему сообщения, какой JSON ожидается, какие вкладки и устройства получают событие и как отклоняются чужие подписки.

Не заменяйте адресную доставку общей рассылкой с фильтром на Frontend. К этому моменту сообщение уже поступило браузеру, который не должен был его получать.

11Надёжность и эффективность

Ниже — проектные рекомендации, вытекающие из ограничений показанного модуля и отправителя, а не описание уже реализованных гарантий.

Сначала сохранить данные, затем уведомить

text
Команда пользователя
    → обычный REST / бизнес-процесс с проверкой прав
    → успешное сохранение и фиксация данных
    → небольшое WebSocket-событие
    → интерфейс перечитывает доступное ему состояние

Не отправляйте сигнал до фактической фиксации изменений: подписчик может успеть прочитать старое состояние. Точная граница транзакции в вашем REST-сервисе или бизнес-процессе должна быть установлена отдельно — её нельзя вывести из данного WebSocket-кода.

Когда потеря уведомления недопустима, нужен отдельный устойчивый механизм: например, сохранение задания на публикацию вместе с бизнес-изменением и последующая контролируемая отправка. Такой механизм в представленных фрагментах не показан и не реализован примерами.

Переподключение не восстанавливает историю

После каждого нового подключения перечитывайте актуальное состояние через защищённый API. Для строгой синхронизации потребуется серверная версия состояния или курсор событий и способ обнаруживать пропуски. Одного event_id недостаточно для доказательства непрерывности потока.

Не отправляйте автоматически повторно пользовательские команды после потери соединения: первая попытка могла уже выполниться. Повторяемые команды требуют прикладного ключа идемпотентности. Это отдельная логика сервера, не свойство SendWSAsync.

Ограничивайте частоту и объём

Каждый вызов SendWSAsync создаёт новое подключение. Не используйте его как высокочастотный поток координат, аудио или постоянных промежуточных изменений формы. Для уведомлений объединяйте несколько изменений в один сигнал «данные обновились».

На Frontend объединяйте пачку сигналов в одно перечитывание и не запускайте параллельно десятки одинаковых Query. В полном примере ограничены очередь, история и размер сообщений; для конкретной формы аналогично ограничьте частоту обновления данных.

Несколько серверных узлов

В присланном модуле список соединений хранится в памяти этого экземпляра. Общая доставка между узлами или процессами не показана. Поэтому нельзя предполагать, что Lua, подключённый к одному узлу, уведомит браузеры другого. Проверьте маршрутизацию и фактический механизм межузловой доставки. Привязка сессии к узлу сама по себе не создаёт общую шину событий.

Heartbeat

Поддержка прикладных ping / pong не установлена. Строка "ping", отправленная через send(), — обычное прикладное сообщение, а не управляющий WebSocket Ping-кадр. Не включайте таймер такого обмена без согласованного обработчика. Управляющие кадры протокола и сообщения приложения — разные уровни. B3, B6

12Безопасность и конфигурация

Права проверяются на сервере. Имя комнаты, поле пользователя и фильтр JavaScript не являются разрешением на доступ. Для всех трёх обработчиков отдельно проверьте аутентификацию, допуск отправителя и подписчика, проверку Origin и границы организации. В присланном коде эти проверки не показаны.

Адрес отправителя задаёт администратор. Не принимайте wsServer и произвольный path из request.input, из имени комнаты без проверки или из request.host. Иначе тестовый издатель может стать способом подключения к нежелательным внутренним адресам.

Транспорт не переносит сессию автоматически. Lua-отправитель не передаёт Cookie/Authorization. У браузерного конструктора WebSocket(url, protocols) нет аргумента для объекта произвольных HTTP-заголовков. Способ авторизации должен соответствовать фактическому обработчику. S3, B1

Содержимое события минимально. До подтверждения изоляции не публикуйте документы, телефоны, токены, персональные данные, названия закрытых объектов или другие чувствительные сведения. Даже ID объекта может быть чувствительным. Для теста используйте фиксированный текст из примеров.

Вывод — как текст. В JIT используйте интерполяцию, в обычном DOM — textContent. Не вставляйте входящее сообщение через innerHTML. Не переходите автоматически по URL из события без проверки разрешённых адресов.

Логи — без содержимого документов и секретов. Обычно достаточно event_id, типа события, транспортного кода, статуса подключения и времени. Это предложенный состав диагностики; встроенного аудита доставки в исходниках нет.
