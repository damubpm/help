Жизненный цикл страницы #

Самый полезный способ понимать страницу — не по сотням строк шаблона, а по цепочке вызовов.

1JIT создаёт классGenClass extends vm.constructor
2ngOnInitдля only_jit_page → restartAll()
3restartAllfilters → fields → tools
4getTableFieldsметаданные колонок
5updateQueryOptions + selection reset
6getTableSortзагрузка items + formatting
Ментальная модель: HTML почти ничего не знает о конкретных колонках. Он получает fields из метаданных и рендерит их по _data_type_code. Поэтому одна и та же схема масштабируется на разные сущности.

Базовая конфигурация JIT-класса #

Обязательные идентификаторы

JIT / конфигурация 
entity_id   = '3352';
entity_code = 'its_d_ga_mnr';
page_id     = '12583';

table_code = this.entity_code;
query_code = 'its_d_ga_mnr';
  • entity_id — нужен для инструментов и массовых БП.
  • entity_code — таблица/сущность для insert/delete и обычно detail route.
  • query_code — запрос, из которого читается список.
  • table_code — код для метаданных колонок и архивного query.

JIT-входные данные

В начале сохраняется вход:

JIT DATA 
const DATA = data;

get only_jit_page() {
    return DATA && Object.keys(DATA).length > 0;
}

Вход может передавать query_code, flt, flteq, fltin, func22, limit, param1, param2, static_filters, show_fields.

Важно: в исходнике одновременно используются DATA и data. Это работает, потому что DATA = data, но при создании новых страниц лучше придерживаться одного соглашения, чтобы не путать «сырой вход» и его локальную копию.

Базовое чтение query 
const q = new Models.QueryOptions('my_query_code');
q.page = 1;
q.perpage = 15;
q.param1 = '...';

this.dbQueryService.getQuery(q)
    .pipe(first())
    .subscribe(table => {
        this.table = table;
        this.filtered = table?.items || [];
    });

Фильтр в заголовке таблицы

Поля меняют field.value, затем вызывается onSubmitFieldFilter(). В обычной странице значения сериализуются в URL query params с префиксом search_; в JIT-режиме вызывается update(params) напрямую.

Статический фильтр

static_filters может прийти через JIT-вход или быть восстановлен из localStorage. Для фиксированных reference-полей дополнительно загружается справочник через _def_sel_query_code.

Практический принцип: при добавлении нового типа поля сначала определите 4 вещи: как хранится значение в UI, как оно сериализуется, в какой контейнер QueryOptions попадает и как показывается в таблице.

CRUD в текущей реализации #

C — Create

add() вызывает /update_v_1_1 с action insert, создаёт sys$uuid, затем идёт на detail route по last_insert_id.

Insert 
const body = JSON.stringify({
  items: [{
    table_name: this.entity_code,
    action: 'insert',
    values: [{ sys$uuid: uuid.v4(), id: 0 }]
  }]
});
this.httpClient.post(environment.apiUrl + '/update_v_1_1', body)

R — Read

Чтение выполняется через dbQueryService.getQuery(this.query_options). Результат сохраняется в table, а строки — в filtered.

U — Update

Список сам по себе не делает inline-update полей. Переход идёт в detail page через goToDetail(), либо detail может быть открыт в JIT/modal и сохранён через jit_page.save().

D — Delete

deleteChecked() отправляет выбранные ID в /update_v_1_1 с action delete. Перед этим confirmDeleteChecked() открывает подтверждение.

Отличие от «классического Angular CRUD»: DamuBPM-страница разделяет чтение и запись: чтение идёт через query abstraction, а изменения — через универсальный update API или через detail/JIT page.

Tools

getTools() читает bp_processes_tools_by_entity_id. В HTML инструменты выводятся как кнопки и запускаются через appComponent.bpRun(tool.code, {}, bindCallBack).

JIT-режим и detail page в модальном окне #

only_jit_page

Если в DATA есть входные данные, подписки на route.queryParams и route.params не создаются. Пагинация и фильтры вместо навигации по URL вызывают update() напрямую.

openPagesAsModal()

Открывает Components.DialogTemplateComponent с type: 'pages', передаёт code: page и получает ссылку на JIT-компонент через getJitComponent. Save вызывает jit_page.save().

Схема модального detail 
this.dialog_ref = this.dialogService.open(
  Components.DialogTemplateComponent,
  {
    header: this.modal_title,
    style: { width: '75%', 'min-height': '75vh' },
    data: {
      buttons,
      data: { detail },
      type: 'pages',
      code: page,
      getJitComponent: jitPage => { jit_page = jitPage; }
    }
  }
);

this.dialog_ref.onClose.subscribe(_ => this.update());

Рецепт: новая CRUD-страница с нуля #

Последовательность

  1. Определить entity_id, entity_code, list query_code и detail page code.
  2. Убедиться, что get_filter_cols_by_code возвращает метаданные нужных полей.
  3. Создать JIT-класс: state → lifecycle → restartAll() → queries.
  4. Реализовать setQueryOptions() и типизацию фильтров.
  5. Подключить p-table к fields и filtered.
  6. Добавить column filters по _data_type_code.
  7. Добавить selection и batch actions, если нужны.
  8. Подключить detail route / modal JIT.
  9. Добавить create/delete через /update_v_1_1, если права и сценарий это допускают.
  10. Проверить обычный и JIT режим отдельно.

Типичные ловушки и диагностика #

Проверьте: query_options.code, param1/param2, сериализацию фильтров, page/perpage, а затем сам table_sorted.items. В текущем коде пустой items нормализуется в [], чтобы шаблон не падал.
Проверьте field._def_sel_query_code. И статические reference-поля, и фильтры таблицы завязаны на этот query code.
В обычном режиме onSubmitFieldFilter() делает router.navigate(), а в JIT — вызывает update(params). Проверяйте ветку only_jit_page и содержимое DATA.
update() сбрасывает selected_all_rows и вызывает setCheckedAll(). Если меняете логику selection, сохраняйте этот инвариант или явно очищайте checked_rows.
Порядок хранится под ключом table_code + '.fields.order'. Если меняется table_code, это уже другой набор настроек.
В условии исходника есть выражение вида (from || to) && type == 'double' || type == 'number'. Из-за приоритета операторов ветка для number может сработать шире, чем визуально читается. Для новых страниц безопаснее писать: (from || to) && ['double','number'].includes(type).
Метод не принимает event, но внутри использует event.target. Если окружение не предоставляет глобальный event, передавайте $event явно: confirmDeleteChecked($event).
Метод создания присутствует в JIT-классе, но в предоставленном шаблоне нет активного вызова (click)="add()". Для новой страницы кнопку надо добавить сознательно с учётом прав и UX.

Самопроверка #

Нажмите «Ответ», чтобы проверить понимание архитектуры.

1. Где определяется, какие колонки показывать?
Метаданные приходят через getTableFields() / query get_filter_cols_by_code, а HTML отображает поля, у которых is_advanced != 1.
2. Чем отличается фильтр reference от text?
Reference идёт в fltin[alias] и использует prime-select-multi; text идёт в flt[alias].
3. Как запускается массовый бизнес-процесс?
ID накапливаются в checked_rows, затем doAct(act) вызывает appComponent.bpRun(act.code, { url: '?code=...&ids=...' }).
4. Что является Write API для add/delete в этой странице?
environment.apiUrl + '/update_v_1_1' с items:[{table_name, action, values}].
5. Почему changePage() имеет две ветки?
Обычная страница сохраняет состояние в URL через router; JIT-страница не меняет route и обновляет данные напрямую.
